# Blackholes 0.1.20

Closing a task no longer loses what was learned in it, your Agents list survives restarts, and agents can find any session and point you to it without pulling you away from your work.

## Changes

- **Closing archives the task.** Its terminals and worktrees are still removed, but the task stays in its project under **Archived**, with its context, links, decisions, branches and the Claude/Codex session IDs that worked on it. Search the archive from the project page, or delete an entry permanently.
- **Decisions.** Record the decisions taken in a task, each with an optional link to where it was decided. They are kept as written, appear in the task's generated context, and survive closing. Agents can record them through the MCP.
- **Tasks without repositories.** Create a task with no repository selected for conversations, research or support. It keeps its context, links and decisions, and you can add repositories later.
- **The Agents list survives a restart.** Sessions stay in the list, with their sections, after you quit Blackholes and when they stop. Click a stopped one to resume it where you left it, as in the project tree. A session leaves the list only when you close it.
- **Pin sessions.** Right-click an agent in **Agents** and choose **Pin to top**. Pinned sessions stay first and show a pin beside the close button.
- **Rename sessions.** Right-click an agent in **Agents** and choose **Rename**. Your name replaces the title the agent sets in the Agents list, the project tree and the task's sessions; leave it empty to show the agent's title again. Agent cards now show the session's name in bold, with its project, task and repository below; the icon identifies the agent.
- **Sections in Agents.** Group sessions in named sections that fold, with a count and a notice dot while folded, and sub-sections up to three levels. Create them from the Agents header or from a session's menu, which also moves sessions between sections; a section's menu edits it, adds a sub-section or deletes it. Press and hold a session or a section, then drag it: sessions move between sections, sections go before, after or inside another one. A button folds or unfolds every section at once. Each session can also have a short note, shown in its tooltip. The project tree does not change.
- **Section descriptions for agents.** A section can have a description that is not shown in the list: agents read it to put each new session where it belongs, such as a code review session in your Code Review section. The MCP tools that start agents accept the section.
- **Unused sessions stand out.** An agent session nobody opened for a week shows its icon in red, and after a month in black, in the Agents list and in the project tree. The tooltip says how many days.
- **Links from your agents, without leaving what you are doing.** Ask an agent "show me which session did this" or "show me this task in Blackholes" and it leaves a link: a small card at the bottom right of its own terminal with the session, project or task and why. Nothing jumps or pops up over your work; you see the card when you come back to that agent, click to go there (a stopped session resumes) or close it. An agent running in Blackholes never moves your view when it opens a task, project or session for you: it leaves the link instead. The new MCP tool is `suggest_navigation`.
- **The project tree follows you.** Whenever you open a session, from the Agents list, a notification, a link, the keyboard or an agent, its row scrolls into view in Projects. Scrolling the tree by hand is never undone.
- **Organize Agents through MCP.** Ask your agent to organize the Agents list: `list_agent_sessions` reads it, with how many days each session has been unused, and `organize_agent_sessions` creates, renames, nests, describes, orders and deletes sections and sets each session's name, note, section and pin in one call. The installed Blackholes skill explains when to use them.
- **Close sessions through MCP.** `close_agent_sessions` closes agent session tabs as the × does: pass their terminal IDs, or ask for the stopped ones, or for those unused for a number of days ("close the ones older than a week"), optionally in one project. Filters never close pinned sessions. Nothing is deleted from disk, and each result keeps the Claude Code or Codex session ID. Running sessions are stopped only when asked, with the same rules as closing a task, and the session making the call is never closed.
- **Closed sessions stay findable.** Blackholes keeps every agent session you close, with the × or by closing its task: its name, section, project and a summary of its conversation, which remains after the provider deletes old transcripts. `list_closed_agent_sessions` finds them by name, project or words from their messages.
- **Read any session, page by page.** `get_agent_session_activity` lets an agent read what another Claude Code or Codex session did, each prompt with its last reply, by terminal or by `providerSessionId`, so also sessions already closed or from archived tasks, even with Blackholes closed. `olderCursor` pages back through long sessions. The first page starts with a summary: first and last message with their dates, number of turns, and whether the agent's last message is a question still waiting for an answer. `includeFiles` lists the files the session created or edited, without their contents.
- **Search past conversations.** `search_agent_sessions` finds a text in the prompts and replies of your Claude Code and Codex sessions, optionally in one project, and returns each session with the turn, an excerpt and the date, ready to read with `get_agent_session_activity`.
- **MCP.** New `add_worktree_group_decision`, `remove_worktree_group_decision`, `list_archived_worktree_groups` and `get_archived_worktree_group` tools. `search_worktree_groups` also searches decisions and archived groups. `create_worktree_group` accepts `withoutRepositories:true`.
- **Repositories deleted outside Blackholes.** Clicking a repository whose folder no longer exists removes it from the project and opens the project, instead of showing an explorer error. **Find new repositories** also clears them. Nothing is deleted from disk, and a repository a task still uses is kept so its worktrees are preserved.

## Install or update

Requires **macOS 13 or later on Apple Silicon**. Download
`Blackholes-0.1.20-arm64.dmg`, open it and drag Blackholes to Applications.
Existing signed installations can use **Check for Updates**.
Save your work and end active sessions before installing or restarting.

## Validation and limitations

- Built with `./scripts/build-release`, including the embedded frontend and Rust binaries. Rust unit tests were run, including archiving on close, keeping decisions through session updates, closing restored and running sessions, the unused-days filter, sub-sections, the closed sessions record, transcript paging, summaries, search and agent links. The sidebar was checked in a browser with real mouse events: dragging sessions and sections, folding every section, the red and black icons and the project tree following the open session. The kept Agents list, closing by age and agent links were also checked in a separate instance of the packaged app.
- Tasks closed before this version were deleted and are not in the archive.
- Resuming an archived task's agent session from Blackholes is not available yet; the archive shows its session IDs.
- Links only point to what is open: a closed session or a closed task cannot be linked, and an agent running outside a Blackholes terminal opens things directly, since it has no terminal to show the card in.
- In the light theme the Codex icon is already almost black, so after a month it barely changes; the red week and the tooltip still show.
- Older Codex sessions that Codex compressed (`.jsonl.zst`) cannot be read or searched yet; search reports how many it skipped. Files changed through shell commands are not listed.
